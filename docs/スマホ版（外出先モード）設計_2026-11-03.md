# 営業AI棒 スマホ版（外出先モード）設計

作成: 2026-11-03　ヒアリング: 作者本人（現役ルート営業）

## 1. 前提（ヒアリングで分かったこと）

| 項目 | 内容 |
|---|---|
| 使う場面 | 外出中。次のアポ・訪問まで時間がない中で、得意先から来た見積り依頼・問い合わせに返したい。PC を開いて落ち着いて確認する時間はほぼ無い。 |
| 依頼の入口 | メール（スマホで受信）と電話が中心。会社によって LINE・ショートメール。工場見学で現行品を見せられ、写真を撮って同等品を調べることもある。 |
| 提出の実態 | 正式見積書はメール添付が多いが、確認が手間でミスも出る。急ぎはメーカー回答が届き次第「いつもの掛率か粗利」で口頭・SMS・メールにベタ打ちで暫定回答し、帰社後に正式見積書を送る。二度手間・漏れ・口頭回答を忘れる、が起きている。 |
| ホームで見たいもの | 訪問 10 分前以内なら次の訪問先の要点。それより前なら「まだ返していないもの」。状況で変わるので切り替えやすく。 |
| 明細の見方 | 必ず明細は見る。ただしポイントだけ確認したい時もある。「送る」はいつでも押せる位置に。 |
| 予定の取得 | まずは Google カレンダーとアプリ内入力。会社ごとに違うので将来は他の連携も。 |
| 暫定回答の扱い | その場で見積りにして「正式未送付」として追跡する。 |
| 値付けルール | 掛率（仕入 × 係数。仕入先で決まる先も得意先で決まる先もある）と粗利％（得意先）が混在。端数は切り捨てで、単位（1 円・10 円・100 円）も得意先ごと。仕入先の回答が掛率ではなく単価だけのこともある。 |
| 送信 | **得意先には直接送らない。** 文面の違和感だけで信用を落としたくない。「自分にメールしてくれる事務員」に徹してほしい。 |

## 2. 設計原則

1. **得意先に直接送らない。** アプリは完成品（見積書 PDF ＋ 文面 ＋ チェック結果）を「自分宛て」にメール、またはスマホの共有メニューに渡す。送るのは人。
2. **30 秒で判断できる画面。** 1 画面 1 目的。「送る」「暫定で回答」は画面下に常時表示。
3. **口頭で答えたことは必ず残る。** 暫定回答は即座に「正式未送付」の見積りになり、帰社後の正式見積書と自動で突き合わせる。
4. **値付けは得意先ルールで自動。** 掛率／粗利／端数の設定から単価を出し、根拠を一行で示す。最終判断は人。

## 3. 画面構成（スマホ）

### 3.1 ホーム「いま」
- 上部に今日の訪問タイムライン（次の訪問先と「あと ◯ 分」）。
- **自動切替**: 次の訪問まで 10 分以内 → 「訪問前ブリーフ」カードを先頭に。それ以外 → 「返事待ち」リストを先頭に。セグメント「返事待ち｜次の訪問」で手動切替も可。
- **返事待ち**（統合リスト）: 電話メモ未処理／貼り付けた依頼の下書き／暫定回答の正式未送付／仕入先回答待ち／担当確認待ち／問い合わせ未回答。期限・経過時間順。各行に「あと何をすれば送れるか」を一行と、次アクションのボタン 1 つ。
- **訪問前ブリーフ（短縮版）**: 担当者、進行中案件と次の一手、返事待ちの見積り、前回の約束、話すこと 5 行（AI）。既存の `/customers/[id]/brief` を 1 スクロールに圧縮。

### 3.2 「依頼を入れる」（＋ボタン）
- **貼り付け**: メール／LINE／SMS の本文を貼る → AI 読み取り → 見積り下書き or 問い合わせ。Android は共有メニューから直接受け取る（PWA の share_target）。iPhone はコピペ。
- **写真**: カメラで現行品・品番ラベルを撮る → 商品特定／同等品候補（ウェブ検索 `kind: equivalent`）→ 見積り明細 or 問い合わせへ。
- **話す**: 既存の電話メモ。
- **メーカー回答を入れる**: 「仕入先回答待ち」の明細に単価・納期・有効期限を入力（回答メールの貼り付けでも可）→ 得意先ルールで販売単価を自動算出 → そのまま暫定回答へ。

### 3.3 見積り「ポイント確認」
- 上部: 得意先・件名・合計・粗利率・警告数。
- 明細カード（コンパクト）: 品名／数量／単価／前回比／根拠一行／警告バッジ。タップで詳細（仕入ルート比較・販売履歴）。
- **下固定バー**: 「暫定で回答」「自分宛てに送る」「正式見積書」。
- **暫定で回答**: SMS・口頭用の短文（品名・数量・単価・納期・有効期限）を生成 → コピー → 見積りを `provisional`（正式未送付）で保存。回答した手段（電話／SMS／LINE／メール）を記録。
- **正式見積書を作る**: 暫定見積りから正式版を作成。口頭で答えた単価・数量と違う箇所を赤で警告。

### 3.4 問い合わせ回答
- 得意先からの質問（仕様・納期・在庫・同等品）を貼る or 話す → 社内記録（過去見積り・仕入先・商品マスタ）＋ウェブ検索 → 回答文面（短文／メール）→ コピー or 自分宛て。回答待ちリストに残り、回答済みにすると消える。

### 3.5 設定（PC）
- 得意先: 値付けモード（掛率／粗利）、係数または粗利％、端数単位（1／10／100 円、切り捨て）。
- 仕入先: 掛率（任意）。
- 自分宛てメール: 宛先アドレス、会社メールの SMTP（使えない場合は共有メニューのみ）。
- 予定: アプリ内入力／Google カレンダー（第一段は非公開 iCal URL の取り込み、第二段は OAuth 連携）。

## 4. データの追加・変更

| テーブル | 追加列 |
|---|---|
| customers | `pricing_mode` (markup / margin), `markup_rate`, `margin_pct`, `rounding_unit` |
| suppliers | `markup_rate` |
| quotes | `status` に `provisional`（正式未送付）を追加。`provisional_at`, `provisional_channel` (phone / sms / line / mail), `provisional_text` |
| quote_items | `supplier_quote_price`, `supplier_quote_delivery`, `supplier_quote_valid_until`, `supplier_quote_at` |
| visits（新規） | `id`, `user_id`, `customer_id`, `starts_at`, `ends_at`, `place`, `source` (manual / ics / google), `external_id` |
| inquiries（新規） | `id`, `customer_id`, `deal_id`, `question`, `channel`, `answer`, `status` (open / answered), `due` |
| users | `self_email`。SMTP 設定は `.env`（`EIGYO_SMTP_*`）に置き DB には入れない。 |

**進捗（2026-11-04）: フェーズ 2 実装済み。** 訪問予定（手入力＋iCal URL／.ics 貼り付け、得意先の自動推定）／ホームの「返事待ち｜次の訪問」自動切替（設定分前・訪問中、手動切替と自動復帰）／訪問前ブリーフ短縮版／メーカー回答の入力（回答メールの AI 読み取り→仕入れ単価・納期・有効期限→いつもの掛率で売単価）。残りはフェーズ 3（問い合わせ回答フロー・写真→同等品・Android 共有ターゲット・Google カレンダー OAuth）。

## 6. 未決事項

- 会社メールの SMTP が外部から使えるか（サーバー・ポート・認証方式）。使えない場合は「共有」でスマホのメールアプリに PDF と文面を渡す。
- 正式見積書の PDF 化。現在は Excel 出力のみ。追加ライブラリ無しで印刷用 HTML から PDF を作る方式を予定。
- 掛率の優先順位（仕入先の掛率と得意先の掛率が両方あるとき、どちらを使うか）。
