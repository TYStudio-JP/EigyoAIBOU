# 問い合わせ回答・返事待ちスキル

## 問い合わせに答える
1. 質問文を `log_inquiry` に渡す（得意先が分かれば `customer` も）。社内記録（取扱品・仕入れルートの最短納期・前回単価・同区分品）と、社内記録だけで書ける回答文の下書きが返る。
2. **数字は社内記録にあるものだけ**使う。無いものは「確認のうえご連絡します」。仕入れ値・他社向け価格・仕入れ先名は得意先に出さない。
3. 仕様や同等品の一般情報が要るときだけ `web_research`（kind: `spec` / `equivalent` / `successor`）で補い、「メーカー公開情報では」と断る。
4. 回答文は短文（SMS・LINE・電話向け 2〜4 行）とメールの 2 通りを示す。送るのは人。送る前に確認すべき点（サイズ違いの可能性、在庫の有無、価格の適用範囲）を箇条書きで添える。
5. ユーザーが送ったら `answer_inquiry` で回答文と手段を記録する（返事待ちから消える）。

## 返事待ちを片付ける
- 「いま何を返せばいい？」は `reply_queue`。急ぎ順（電話メモ未入力 → 問い合わせ未回答 → 正式未送付 → 見積り未提出 → 納期回答待ち → そろそろ確認）。各行の `todo` が「あと何をすれば返せるか」。
- 口頭・SMS で単価を先に伝えたら `mark_provisional`（下書きは提出済になり、正式見積書は「未送付」として残る）。短文も返るのでそのまま使える。
- 正式見積書を送る前は `mark_formal_sent` を `check_only: true` で呼び、口頭で伝えた単価・数量との差があれば先に直す。送ったら `check_only` 無しで記録。

## 作法
- 得意先に直接送らない。営業AI棒は文面と事実を揃えるだけで、送信は営業担当がいつもの文面で行う。
- 在庫数は持っていない。在庫を聞かれたら「仕入れ先に確認」を次の一手にする。
