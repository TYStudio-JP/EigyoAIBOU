# 営業AI棒（えいぎょうあいぼう）

> **全ルート営業マンに効率化を。めんどくさい仕事を排除して。**
> 商談・訪問・電話以外の仕事 ── 見積り作成、価格の確認、見積りの追跡、提案ネタ探し、仕入れ先への問い合わせ ── を肩代わりする、モノ売り法人営業のための相棒です。

Built with Claude: Japan 2026 提出作品（テーマ #1「あなたにしかない深さを」）。
作者は東証プライム企業・専門商社・総合商社で 12 年、法人営業（代理店・特約店・新規・既存）を続けてきた現役の営業担当です。
「売上をつくるのは人と人の信頼関係。そこに時間を使えるように、それ以外を全部やってくれる相棒が欲しい」── その一点から設計しました。

制作の出発点になった記録は `docs/` にあります。
- [当初の困りごとと実装の対応表](docs/当初の困りごとと実装の対応表_2026-11-04.md)：作者が AI を使わず自分で書いた困りごとメモと、機能ひとつずつの対応
- [スマホ版（外出先モード）設計](docs/スマホ版（外出先モード）設計_2026-11-03.md)：現役営業へのヒアリングから決めた前提と設計原則

## 何ができるか

| 営業の仕事 | 営業AI棒がやること |
|---|---|
| **見積り作成** | メール本文・電話メモ・Excel/PDF 添付をそのまま読ませると、商品を特定し、**得意先ごと／商品ごと／仕入れ先ごとの過去価格と原価を照合**して単価を提案。歴史（前回単価）を大切にしつつ、**原価割れ・前回より値下げ・他社売価との乖離・もっと安い仕入れルート・最小ロット未満**を警告。Excel 見積書を出力。 |
| **見積り追跡** | 提出済み案件を「そろそろ確認すべき」順に並べ、**フォローのメール文面と電話トーク**を経緯を踏まえて下書き。受注／失注と理由を記録し、失注理由の傾向をダッシュボードに出す。 |
| **横展開提案** | 得意先コード・業種・購買履歴から「同業 A で売れているが同業 B は未購入」の商品を根拠付きで抽出し、**商談の切り出し・一言提案・想定反論・提案メール**を作る。 |
| **商品問い合わせ** | 仕入れ先ルート（メーカー直／代理店／商社）ごとの原価・最小ロット・納期を一覧し、**メーカー・仕入れ先への納期／価格問い合わせメール**を下書き。 |
| **納期の記録** | 得意先の希望納期と、仕入れ先リードタイムから算出した回答納期を見積りに保持。 |

| **電話メモ** | 電話を切った直後にスマホで 30 秒話すだけ。Claude が**議事録と依頼事項**（商品問い合わせ・価格相談・納期相談・見積り依頼・数量変更・クレーム）に分け、依頼ごとに価格照合・納期算出・見積り下書きを実行し、得意先宛ての**確認メール「お電話の件、以下の通り承りました」**を下書き。口頭のミス・漏れを無くします。Android は通話終了を自動検知して画面を開きます。 |

| **案件管理** | 得意先 × ひとつの話を「案件」として、見積り・電話メモ・フォロー・確認メールを自動で束ねます。**新規か既存かは営業AI棒が判定**（見積番号・商品・担当者・語の一致・直近性で採点し、迷えば Claude が裁定）。状態は見積りと電話から自動で決まり、「ここまでの経緯と今の状況」を 3 行＋詳細で要約し、次の一手と期限を置きます。間違った紐づけはワンタップで直せます。 |
| **担当者・納入先・引継ぎ** | 得意先の担当者（在籍・異動・退職）を名刺の写真から登録。ディーラーの場合は「誰がどの納入先を見ているか」を案件から集計。担当者ごとの対応量（電話・見積り・案件数）で見えない工数を把握。**得意先の担当を別ユーザーへ引き継ぐ**と、引継ぎ書が保存され、各案件に「ここまでは前回の担当者〇〇」が明記され、前任者には「過去の担当先」として残ります。 |

| **伝票計上の指示** | 受注した見積りから、事務員向けの計上指示（得意先コード・商品コード・仕入れ先コード・単価・納期）を Excel で出力。見積りや過去の受注単価と違う点、未登録品、納期未回答を赤く示します。 |
| **営業日報** | その日の電話・見積り・フォロー・受注失注・案件の動きから日報の下書きを自動生成。一言メモを足して AI が清書。保存・コピーして提出。 |
| **納期回答待ち** | 仕入れ先の納期回答が無い明細を一覧し、回答を入れると回答納期が見積りに反映。希望納期に間に合わないときは分納・代替の提案を含む得意先向け連絡文を出します。 |
| **訪問前ブリーフ** | 訪問直前にスマホで開く 1 ページ。担当者、進行中の案件と次の一手、直近の電話、返事待ちの見積り、定番品、横展開候補、前任者の申し送り。AI で「今日話すこと 5 行」にできます。 |
| **価格改定の影響** | 現在の仕入れ値（または値上げシミュレーション）で、直近の受注単価だと粗利下限を割る得意先×商品を「取り戻すべき額」の大きい順に一覧。値上げ交渉の順番を決めます。 |

| **ウェブで調べる** | 商品の仕様・規格・相場・メーカー情報・得意先の会社情報を Claude のウェブ検索で調べ、出典 URL 付きで要約。チャット、仕入れ先問い合わせ画面、商品ページから使えます。 |
| **問い合わせ回答** | 得意先からの質問（仕様・納期・在庫・同等品・価格）を貼るか話して記録。社内記録（取扱品・仕入れ先の納期・前回単価・同区分品）を集め、Claude が短文（SMS・LINE）とメールの回答文を下書き。必要ならウェブも調べて出典付きで補う。仕入れ値や仕入れ先名は得意先に出さない。送るのは人。 |
| **写真で調べる** | 工場で見た現行品のラベル・刻印を撮ると、品番・品名を読み取って自社の取扱品と照合し、同等品・後継品をウェブで調べる。Android は共有メニューから写真やメールを直接営業AI棒へ。 |
| **訪問予定とホームの切替** | 訪問予定をアプリで入力するか、Google カレンダー等の非公開 iCal URL から取り込み、または Google アカウントと OAuth 連携（予定の社名から得意先を自動で当てる）。**次の訪問の 10 分前になるとホームが「次の訪問」（担当者・案件・返事待ち・前回の約束・話すこと 5 行）に自動で切り替わり**、それ以外は「返事待ち」。手動切替も可。 |
| **メーカー回答の入力** | 仕入れ先の回答メールを貼ると単価・納期・有効期限・最小ロットを読み取り、得意先ごとの**いつもの掛率／粗利で売単価まで自動**。そのまま暫定回答へ。 |
| **外出先モード（スマホ）** | ホームの**返事待ち**（電話メモ未入力・正式未送付・見積り未提出・納期回答待ち・そろそろ確認）を急ぎ順に。見積りは**ポイント確認**画面（明細カード＋根拠一行＋警告）で、画面下に常時「暫定で回答」「自分宛てに送る」。**暫定で回答**は SMS・LINE・電話用の短文を作り「正式未送付」として追跡、帰社後の正式見積書と口頭回答の差を赤で警告。**自分宛てに送る**は見積書 Excel と転送用文面を本人のメール（SMTP）か共有メニューへ──得意先には直接送りません。得意先ごとの**値付けルール**（掛率／粗利％／端数切り捨て単位）でメーカー回答から即答できます。 |
| **質問する（チャット）** | 「東海精密にエンドミル 10 本、いくらで出せる？」「納期回答待ちは？」「みどり食品に提案できる商品は？」と聞くと、営業AI棒が検索・価格照合・案件・電話メモ・日報の道具を使って事実から答えます。見積りの下書き作成やフォロー記録も会話から行えます。音声入力対応。 |

最終判断は必ず人が行います。営業AI棒は「根拠」と「選択肢」を 30 秒で読める形に整えるだけです。

**スマホが主役です。** 営業中・外出中に電話メモ、見積り、追跡、横展開提案がスマホだけで完結します。マスタ登録や設定はデスクトップから行います。

## セットアップ（Windows / Mac 共通・無料）

必要なものは **Node.js 22 以上**（[nodejs.org](https://nodejs.org/) の LTS）だけです。ネイティブモジュールは使っていないので、Windows でも Visual Studio Build Tools 等は不要です。

```bat
git clone https://github.com/TYStudio-JP/EigyoAIBOU.git
cd EigyoAIBOU
npm install
npm run dev
```

ブラウザで http://localhost:3000 を開きます。初回起動時に架空のダミーデータ（得意先 14 社・仕入れ先 8 社・商品 37 点・見積り約 170 件）が自動投入されます。

### AI 機能を使う（推奨）

リポジトリ直下に `.env` を作り、Claude API キーを書きます（`.env.example` をコピー）。

```
ANTHROPIC_API_KEY=sk-ant-...
```

再起動すると、依頼文の読み取り・フォロー文面・提案トーク・提出前レビューが Claude で動きます。
キーが無い場合は正規表現による簡易抽出モードで動作し、価格照合・警告・追跡・横展開は全機能使えます。
モデルは既定で `claude-opus-5-5`。コストを抑えるなら `.env` に `EIGYO_MODEL=claude-sonnet-5-5` を追加してください。

### スマホから使う（外出先でも）

PC で `npm run dev` を動かしたまま、もう一つのターミナルで次を実行します。

```bat
npm run tunnel
```

Cloudflare の無料トンネルで `https://xxxx.trycloudflare.com` のような URL が表示されます。スマホでその URL を開き、Safari（iPhone）なら共有メニューの「ホーム画面に追加」でアプリのように使えます。

- **必ず `.env` に `EIGYO_ACCESS_KEY=好きな合言葉` を設定してください。** URL を知っている人は誰でも開けるためです。表示される `?key=...` 付きの URL を一度開くとスマホに記憶されます。
- スマホで本格的に使うときは、開発サーバー（`npm run dev`）ではなく本番モードで動かしてください。開発モードは画面の再読み込みが頻繁に入り、トンネル越しだとタップが効かないように見えることがあります。

```bat
npm run build
npm start
```
- 音声入力は iPhone は Safari、Android は Chrome で動きます。使えない場合はキーボードのマイクボタンで同じ欄に話せます。
- トンネルの URL は起動のたびに変わります。固定したい場合は Cloudflare アカウントで名前付きトンネルを作るか、VPS 等に配置してください。

### Android で通話終了を自動検知する（任意）

無料の自動化アプリ **MacroDroid** を使うと、電話を切った瞬間に営業AI棒の電話メモ画面が開きます（iPhone は仕組み上できないため、ホーム画面の「☎ 電話メモ」ボタンを押します）。

1. MacroDroid で新しいマクロを作成し、トリガーに「通話終了」を選ぶ。
2. アクションに「Web サイトを開く」を選び、`npm run tunnel` が表示する次の URL を入力する。
   `https://xxxx.trycloudflare.com/api/calls/incoming?tel=[call_number]&duration=[call_duration]&direction=in&key=合言葉`
3. 保存。次の通話終了後、相手の番号を得意先マスタと照合した状態で電話メモ画面が開きます。

### 自分宛てメール（任意・SMTP）

営業AI棒は得意先に直接メールを送りません。スマホから「自分宛てに送る」を押すと、見積書（Excel）と転送用の文面を**自分のメール**に届け、いつもの文面で転送するのは本人です。会社メールの SMTP を `.env` に書くとアプリから送れます（未設定ならスマホの共有メニュー／メールアプリに渡します）。

```
EIGYO_SELF_EMAIL=you@example.jp
EIGYO_SMTP_HOST=smtp.example.jp
EIGYO_SMTP_PORT=587
EIGYO_SMTP_USER=you@example.jp
EIGYO_SMTP_PASS=（メールのパスワードまたはアプリパスワード）
```

会議・出張で自分から送れないときの**代理送付**（アプリから得意先へ直接）は、設定 → ユーザーで許可した人だけ、画面で宛先・金額・文面を確認してチェックを入れたときに限り送れます（CC に本人、履歴が残ります）。

### カレンダーから訪問予定を取り込む（任意）

訪問予定画面で Google カレンダー等の**非公開 iCal URL** を貼ると取り込めます（予定の社名から得意先を自動で当てます）。次の訪問の 10 分前になると、ホームが「返事待ち」から「次の訪問」（担当者・案件・返事待ち・前回の約束・話すこと）に自動で切り替わります。

Google アカウントとの OAuth 連携を使う場合は、Google Cloud で OAuth クライアント（ウェブ）を作り、リダイレクト URI に `{公開URL}/api/google/callback` を登録して `.env` に書きます。

```
GOOGLE_CLIENT_ID=xxxx.apps.googleusercontent.com
GOOGLE_CLIENT_SECRET=xxxx
```

### Android の共有メニューから渡す（任意）

`npm run tunnel` の HTTPS URL を Chrome で開き「ホーム画面に追加」すると、メールや写真の共有先に営業AI棒が出ます。共有すると「見積りを作る／問い合わせに回答／写真から商品を調べる」を選ぶ画面に届きます。iPhone は共有先に出ないため、本文をコピーして同じ画面（`/share/pick`）に貼り付けてください。

### 自社書式の見積書（任意）

設定 → 見積書の書式 から「サンプル xlsx」を取り、セルの `{{quote_no}}` `{{customer.name}}` `{{item.description}}` などの差し込み位置を自社の書式に合わせて登録すると、以後の Excel 見積書はその書式で出ます（明細行は自動で複製）。PDF は見積りの「印刷・PDF」からブラウザの「PDF に保存」で作れます。

|---|---|
| `npm run dev` | 開発サーバー起動（http://localhost:3000） |

## Claude Code との連携（MCP・スキル・サブエージェント・フック）

このリポジトリを Claude Code で開くと、営業AI棒を **会話で操作**できます。

```
> みどり食品からこのメールが来た。見積り作って。
  （メール本文を貼り付け）
```

| 仕組み | 内容 |
|---|---|
| **MCP サーバー**（`.mcp.json` / `packages/mcp-server`） | `search_customers` `search_products` `price_history` `propose_price` `extract_request` `create_quote` `get_quote` `list_quotes` `followup_queue` `record_followup` `set_quote_status` `cross_sell` `lost_reasons` `log_call` `list_calls` `list_deals` `get_deal` `refresh_deal` `list_contacts` `handover_customer` `keijo_check` `delivery_waiting` `record_delivery` `price_impact` `daily_report` `visit_brief` `web_research` `reply_queue` `mark_provisional` `mark_formal_sent` `log_inquiry` `list_inquiries` `answer_inquiry` の 33 ツール。Web アプリと同じ SQLite とロジックを共有するので、Claude Code で作った見積りは即座に画面に出ます。 |
| **スキル**（`.claude/skills`） | `eigyo-quote`（見積り作成の手順）、`eigyo-followup`（追跡と失注記録）、`eigyo-crosssell`（横展開提案）、`eigyo-inquiry`（問い合わせ回答・返事待ち・暫定回答）。警告の扱い方や「他社名を出さない」等の営業の作法を手順に落としています。 |
| **サブエージェント**（`.claude/agents`） | `pricing-auditor`（全明細の価格監査、提出可否を数字だけで判定）、`followup-writer`（経緯を読んでフォロー文面を書く）。どちらも Sonnet で軽く動かします。 |
| **フック**（`.claude/settings.json`） | `packages/core` を編集した直後に型チェックを自動実行（価格ロジックの破壊を即検知）。`data/eigyo.db` を消す／テーブルを落とすコマンドをブロック。 |
| **CLAUDE.md** | 構成・約束ごと（価格判断は人が最終決定、実在企業名を入れない、API 呼び出しは `ai/` に集約）。 |

Windows で `.mcp.json` の起動に失敗する場合は、`"command": "node"` が PATH にあることを確認してください（`npx` ではなく `node --import tsx` で起動する構成にしています）。

```

├─ apps/web/                 Next.js 16（App Router）画面と API
│   └─ src/components/       見積りエディタ・追跡ボード・横展開パネルなど（@eigyo/core/shared のみ import）
├─ packages/core/            ドメインロジック（Web と MCP で共有）
│   └─ src/
│      ├─ db/                node:sqlite（ネイティブ依存なし）とスキーマ
│      ├─ domain/pricing.ts  価格提案と 9 種類のチェック
│      ├─ domain/crosssell.ts 同業判定（業種 + 購買カテゴリ Jaccard）と候補スコア
│      ├─ domain/followup.ts 追跡キューと失注集計
│      ├─ domain/call-actions.ts 電話の依頼事項を種類別に実行（価格・納期・見積り・変更・クレーム）
│      ├─ domain/deals.ts     案件の自動紐づけ（採点＋AI 裁定）、状態導出、時系列、既存データのまとめ直し
│      ├─ domain/handover.ts  引継ぎ書の事実リストと、担当ユーザーの引継ぎ処理
│      ├─ domain/excel.ts    Excel 見積書の出力／得意先 Excel の読み取り
│      ├─ ai/                Claude 連携（構造化抽出・フォロー文面・提案・レビュー・問い合わせ）
│      └─ seed/              架空のダミーデータ生成（決定的乱数で毎回同じ）
├─ packages/mcp-server/      MCP サーバー（stdio）
├─ .claude/                  スキル・サブエージェント・フック
├─ .mcp.json / CLAUDE.md
└─ data/eigyo.db             生成される SQLite（Git 管理外）
```

### 価格エンジンのルール（`domain/pricing.ts`）

1. **提案単価**：同じ得意先への直近の受注単価 → 無ければ他社向け平均 → 無ければ最安仕入れに推奨粗利を乗せた価格 → 無ければ定価。原価が上がって粗利下限を割る場合は下限価格まで引き上げ、その旨を根拠に書く。
2. **値引き下限**：最安仕入れ ÷ (1 − 粗利下限)。「ここまでなら下げられる」を常に表示。
3. **チェック**：原価割れ（danger）／粗利下限割れ・前回より値下げ・他社向けより安い・最小ロット未満（warn）／前回より値上げ・他社向けより高い・より安い仕入れルート・販売実績なし（info）。前回単価を踏襲しているときは他社との整合チェックを省く（既に合意済みの価格のため）。
4. しきい値（粗利下限 15%・推奨 25%・値下げ警告 3%・フォロー 3 日／7 日）は設定画面で会社ごとに変更可能。

### Claude の使いどころ

| 処理 | 方式 |
|---|---|
| 依頼文（メール・メモ・PDF・画像・Excel）の構造化 | `messages.parse` + zod 構造化出力。PDF/画像は document/image ブロックで直接渡す。Excel は exceljs でテキスト化。 |
| 電話メモの議事録化と依頼分類、確認メール | 音声入力の話し言葉を構造化（数量・価格・納期・品番・約束を必ず拾う）。依頼の実行は決定的なコード、その結果だけを使って確認メールを書く（数字を作らせない）。 |
| 案件の新規／既存判定と要約 | まず決定的な採点（見積番号・商品・担当者・語・直近性）。確信が持てない時だけ候補の要約を Claude に見せて裁定（`effort: low`）。要約は時系列から 3 行＋詳細＋次の一手を書き、AI が無い環境では決定的な要約に落ちる。 |
| チャット（質問する） | SDK の tool runner で、Web・MCP と同じドメイン関数を道具として渡す（`ai/chat.ts`）。数字は道具の結果からのみ、書き込み系の道具は依頼が明確なときだけ。履歴はユーザーごとに保存。 |
| 名刺の読み取り・引継ぎ書 | 名刺画像を image ブロックで渡して構造化。引継ぎ書は機械的に作った事実リストを Claude が後任向けに整える（事実に無いことは書かない）。 |
| フォロー文面・仕入れ先問い合わせ・横展開提案・提出前レビュー | 同上。経緯（activities）や機械チェック結果をプロンプトに入れ、根拠付きで書かせる。 |
| 安全分類器で拒否された場合 | `fallbacks: "default"` で別モデルに自動フォールバック。 |
| システムプロンプト | 固定文言を `cache_control` でキャッシュ。役割ごとの追記は後ろに置く。 |

価格計算そのものは Claude に任せず、決定的なコードで行います（監査可能・再現可能・API 障害時も動く）。

## マスタの取り込み（設定 → マスタの取り込み）

会社で使うときは、得意先・仕入れ先・商品・仕入れ価格・売上実績を基幹システムの CSV から取り込みます。設定画面（デスクトップ）で「CSV を選ぶ → 列の対応を確認 → 取り込む」の 2 ステップです。UTF-8 と Shift_JIS を自動判定し、「得意先CD」のような列名は同義語で自動的に当たります。列の対応は種別ごとに保存され、次回から自動です。コードが一致すれば更新、無ければ追加で、**CSV に無い列の既存値は消しません**。

| 取り込むもの | 元データ | 方法 |
|---|---|---|
| 得意先 | 基幹の得意先マスタ CSV（得意先コード・社名・業種・住所・電話・支払条件） | 得意先コードをキーに upsert（`upsertCustomer`）。業種が無ければ初回だけ人が付ける（横展開の同業判定に使う）。 |
| 担当者 | 名刺アプリのエクスポート CSV、または名刺写真 | 社名で得意先に紐づけて upsert。名刺アプリ側の退職者は「退職」として取り込み、履歴に残す（消さない）。 |
| 商品 | 基幹の商品マスタ CSV（自社商品コード・品番・品名・メーカー・カテゴリ・単位・定価） | 商品コードをキーに upsert（`upsertProduct`）。カテゴリが無い場合は品名から AI が候補を付け、人が確認。 |
| 仕入れ価格 | 仕入れ先ごとの価格表 Excel、基幹の仕入れ単価マスタ | 商品コード×仕入れ先コード×適用日で追加（`addSupplierPrice`）。上書きせず履歴として持つので、価格改定の影響一覧がそのまま動く。 |
| 売上・見積り実績 | 基幹の売上明細 CSV（得意先コード・商品コード・数量・単価・日付） | 「受注済みの見積り」として取り込み（`createQuote` + `status: won`）。これで初日から過去価格の照合と案件のまとめ直しが効く。 |

- 担当者は名刺アプリの CSV ではなく、名刺の写真から登録する形にしています（`/contacts/new`）。
- 売上実績は同じ伝票番号（無ければ得意先×日付）の行を 1 つの「受注済み見積り」にまとめます。これで初日から過去価格の照合と案件のまとめ直しが効きます。
- 夜間の自動取り込みが要る会社向けに、同じ関数（`commitImport`）をコマンドから呼ぶ入口は今後追加できます。
- 得意先マスタに「営業担当」の列があれば、ユーザー名（氏名、またはひとりに決まる姓）で担当に割り当てます。
- 空欄のセルは「変更なし」です。数値の列（掛率・納期・定価など）も 0 で上書きしません。
- 取り込んだ売上実績は、画面から取り込むと古い順に案件へ自動でまとまります。
- **デモ動画で使っている CSV と素材一式**は [`demo/`](demo/README.md) にあります（得意先・仕入れ先・商品・仕入れ価格・売上実績の CSV、見積り依頼メールと Excel、電話メモ、メーカー回答、iCal、名刺と商品ラベルの画像、見積書テンプレート）。同じフォルダの README に手順と期待される結果を書いてあるので、動画と同じ操作をそのまま再現できます。
